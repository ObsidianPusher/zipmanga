# 阅读体验与列表导航优化

用户已要求执行全部建议，并为书库、收藏、历史增加底部分页。直接在当前工作区实施，不提交或部署。

## 约束与接口

- 保持 Go 标准库 HTTP、SQLite、原生 JS，无产品依赖增加。
- 图片 API 新增 quality=economy|standard|original，direction=forward|backward；原图不进入有损 raw 缓存。
- 明确区分可确认的页末、网络故障和解码失败；不得由失败推断总页数。
- 新增每本阅读状态 API GET/PUT /api/comics/{id}/reader-state，包含 settings、page_offset、updated_at；服务端时间序列解决迟到覆盖，保留旧进度兼容。
- 历史 API 保留默认返回兼容，支持 page/page_size 及 total/total_pages。
- 前端设置：模式、适配、画质、增强、方向、双页封面偏移，按用户与漫画保存。
- 下一册只在同挂载同目录中自然排序，并提供选择，不猜系列元数据。

## 风险与验证重点

慢请求返回不得覆盖新页；放大拖动不得翻页；401 不应变成页末；同名漫画状态不得新建串用；重启/离开页面不得丢最近页；分页空集合/末页/跳页范围一致；手机横竖屏/双页跨页/未知页数需验证。

原始业务规则继续保留，新增每本状态与旧文件名进度隔离。更改旧收藏去重身份需要另行迁移，不能无证据合并或拆分历史用户数据。

## 已验证结果与运行方式

- Go 全套与 db/server race 检查通过；原图字节、页末错误、时间冲突、同名隔离、历史分页有后端行为测试。
- `node --test tests/reader-core.test.cjs`：适配、双页边界、分页边界和恢复时间顺序。
- `tests/reader-browser.cjs` 使用独立启动的测试服务登录，漫画 API 由 Playwright 拦截；覆盖三个列表底部跳页、滑条预览、失败保留进度/重试、缩放阻止翻页、双页正反边界、输入焦点、未知总页数恢复、滚动图片窗口和每本状态恢复。
- 浏览器测试需自行安装 Playwright，并设置 `TEST_BASE_URL`、`TEST_USERNAME`、`TEST_PASSWORD`；依赖可由 `PLAYWRIGHT_MODULE` 指向外部安装路径。运行 `node tests/reader-browser.cjs`。测试只用于一次性实例，避免污染正常浏览器的进度或列表状态。
- 当前完成 Chromium 桌面和手机视口交互验证；真实设备双指手势、真实远程源网络延迟和大 PDF 仍应上线前实测。未部署或改动运行中的服务。
